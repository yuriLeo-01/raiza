# Notas da tarefa T06: `raiza-ctl`

## O que foi feito

`crates/raiza-ctl` completo: `list`, `get <id>`, `set <id> <capacidade> …`, `watch` e `completions <bash|zsh|fish>`.
`--json` em `list`, `get` e `watch` (no `watch`, um objeto por linha: `{"event":"device_added|device_removed|capability_changed", …}`).

Módulos (lógica separada do I/O):
- `cli.rs`: clap (derive) e `SetCommand::to_value` → `CapabilityValue`. `rgb` exige `--mode` ou `--color` (grupo do clap).
  `rumble` aceita intensidade de 0 a 100. `mute`/`connection` aceitam `on|off`.
- `format.rs`: funções puras de texto (`format_list`, `format_device`, `format_event`, `event_json`).
- `errors.rs`: mensagens em português. Daemon fora do ar (`ServiceUnknown`, `NameHasNoOwner`, `Spawn.*`) →
  "o daemon não está rodando; inicie com: systemctl --user start raizad".
- `run.rs`: conversa com o daemon (`run`, `watch`) e os testes ponta a ponta.
- `main.rs`: conecta, confere `API_VERSION` e traduz erro em código de saída 1 (uso errado: 2, do clap).

Detalhes:
- O `connect` chama `version()` antes de qualquer comando: serve de teste de vida (sem isso o `watch` ficaria
  esperando para sempre sem daemon) e recusa API de versão diferente.
- `raiza-ctl watch | head` (pipe fechado) sai com 0, sem mensagem.
- Sinais ilegíveis no `watch` viram um aviso em stderr e o fluxo continua.

## Testes

- Parsing de cada forma do `set`, válidas e inválidas (`cli.rs`).
- Formatação de `list`, `get`, eventos de `watch` em texto e JSON (`format.rs`).
- Ponta a ponta com servidor D-Bus falso por conexão p2p (`run.rs`): `list`, `get` (texto e JSON), `set` com
  sucesso, `OutOfRange`, `ReadOnly`, `Unsupported`, `NotFound`, e eventos de `watch`.
- Não há teste automático da detecção "daemon fora do ar" via D-Bus de verdade (precisaria de um barramento de
  sessão); só do reconhecimento dos nomes de erro. Verifiquei à mão: sem o `raizad`, `raiza-ctl list` imprime a
  mensagem e sai com 1.

## Para o líder

- **`raiza-core` com a feature `dbus` não compila sozinho**: `crates/raiza-core/src/dbus.rs` usa `StreamExt::boxed` e
  `select_all` de `futures-util`, mas o `Cargo.toml` do core declara `futures-util` com `default-features = false`.
  Os testes do core só passam porque o dev-dependency `futures` liga as features padrão. Contornei no `raiza-ctl`
  declarando `futures-util = "0.3"` (com as features padrão), mas o certo é corrigir no core
  (`features = ["std"]` ou `["alloc"]`). Quem usar `raiza-core/dbus` sem isso (o `raizad`, o `raiza-gtk`) vai esbarrar.
- `Cargo.lock` mudou (clap, clap_complete e dependências novas).

## Como testar com hardware real

Depois da T04: `systemctl --user start raizad` (ou `cargo run -p raizad`), depois:

```sh
cargo run -p raiza-ctl -- list
cargo run -p raiza-ctl -- get usb:3142:a010:0
cargo run -p raiza-ctl -- set usb:3142:a010:0 volume 50
cargo run -p raiza-ctl -- watch          # em outro terminal, mude o volume e veja a linha "~"
```
