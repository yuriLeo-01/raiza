## ⚠ Para o líder: app id = nome D-Bus do daemon
O app id pedido na ficha (`io.github.yurileo01.Raiza`) é **o mesmo** `raiza_core::DBUS_SERVICE`.
O `GApplication` tenta ser dono do nome do seu app id: com o `raizad` rodando, o app falhava ao
registrar (`Failed to register ... org.gtk.Actions`); com o daemon parado, o app **tomaria o nome
do daemon** e o `raizad`/`raiza-ctl` falariam com a interface.

Contorno aplicado (dentro do escopo): o app sobe com `gio::ApplicationFlags::NON_UNIQUE`, então não
pede nome no barramento. Efeitos colaterais: abrir o app duas vezes abre duas janelas, e não dá para
usar `DBusActivatable=true` no `.desktop`.

Sugestão (muda contrato, decisão sua): renomear o serviço do daemon para algo como
`io.github.yurileo01.Raiza.Daemon` (ajustar `raiza-core`, `docs/DBUS.md` e
`packaging/systemd/io.github.yurileo01.Raiza.service`), e então tirar o `NON_UNIQUE` do `main.rs`.

  `cargo test --all-features` passam (18 testes no raiza-gtk, sem GTK: agrupamento, ordem, texto das

- Contra o `raizad --mock`, num gnome-shell headless num barramento isolado
  (`dbus-run-session`, `gnome-shell --headless --virtual-monitor`), com capturas de tela:
  1. lista com "Mouses" e "Headsets", bateria na barra lateral, página do mouse com as 5 capacidades;
  2. `raiza-ctl set other:mock:mouse dpi 800`: a linha DPI mudou de 3200 para 800 na hora, sem recriar
     a página (log: `CapabilityChanged(.., Dpi)`);
  3. matando o daemon: estado "O serviço do Raiza não está rodando" com "Tentar de novo";
  4. subindo o daemon de novo: a janela reconectou sozinha e voltou à lista.
  Para capturar a tela do shell headless, o script toma o nome `org.gnome.SettingsDaemon.MediaKeys`
  no barramento isolado (o shell só aceita `Screenshot` de nomes da lista dele).
- Não testado na tela: o par Removed+Added de verdade (o mock não remove dispositivos pelo
  `raiza-ctl`; coberto pelos testes do modelo) e a janela estreita (breakpoint).
