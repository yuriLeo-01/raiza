# Notas da tarefa T05: Provedor udev (descoberta e hotplug)

## O que foi feito

Crate `crates/raiza-provider-udev` (id do provedor: `"udev"`), em camadas:

- `src/tree.rs`: `Node`/`Tree`, retrato serializável (JSON) da árvore udev. É tudo o que a
  lógica enxerga, então os testes rodam com fixtures em `tests/fixtures/*.json`.
- `src/source.rs`: trait `UdevSource` (`snapshot` + `watch`) e a implementação real
  `SystemUdev` (crate `udev` 0.9 com a feature `send`, sem root). Lê os subsistemas `usb`,
  `input`, `hidraw`, `sound` e `hid`, copiando só os atributos sysfs necessários.
- `src/scan.rs`: lógica pura árvore → `Vec<DeviceInfo>`.
  - Agrupa interfaces/hidraw/input pelo `usb_device` pai: um aparelho USB = um dispositivo.
  - Id: `DeviceId::usb(vid, pid, DeviceId::usb_instance(serial, porta, portas_sem_serial))`,
    com `portas_sem_serial` calculado sobre **todos** os dispositivos USB (inclusive os ignorados).
  - Ignora: root hubs, classe 09 (hub), 08 (armazenamento), e0 (adaptador Bluetooth), e
    aparelhos internos sem interface HID. "Interno" = `removable=fixed` em todo o caminho
    até o root hub. Assim o controle USB do LG (fixo, mas atrás do hub do monitor) aparece.
  - Tipo, nesta ordem: protocolo de boot HID da interface de menor número (teclado/mouse;
    separa mouse com teclas extras de teclado com interface de mouse) → classe de áudio
    01 (nome com "headset/headphone" → Headset, com "mic" → Microphone; senão só captura →
    Microphone, com saída → Headset) → `ID_INPUT_KEYBOARD/MOUSE` (vence a interface de menor
    número) → `ID_INPUT_JOYSTICK` sem teclado/mouse → Gamepad → `ID_INPUT_TOUCHPAD` → Mouse → `Other`.
  - Bluetooth: nós `input` com `ID_BUS=bluetooth`, agrupados por `DeviceId::bluetooth(uniq)`.
    Nome do `HID_NAME` do nó `hid` pai (sem o sufixo " (AVRCP)"). Só nós AVRCP → Headset.
    Sem `uniq` válido: ignorado com log `debug`.
- `src/provider.rs`: `UdevProvider` (`Provider`).
  - `discover`: udev ausente → lista vazia + log `info`.
  - `read`: só `Connection` (relê a árvore); outro tipo → `Unsupported`; id sumido → `NotFound`.
  - `write`: sempre `ReadOnly(Connection)`, nada toca o hardware.
  - `events`: `udev::MonitorBuilder` + `tokio::io::unix::AsyncFd`, sem polling. A cada rajada
    de eventos (`add/remove/bind/unbind`), espera 300 ms de silêncio (máx. 2 s), relê a árvore
    e emite a diferença (`diff`). Ao iniciar a vigília, relê uma vez para cobrir o intervalo
    desde o `discover`. Não usa `tokio::spawn`: o fluxo se dirige sozinho e acaba quando é descartado.
- `examples/listar.rs`: lista com o `DeviceId` e acompanha hotplug. `-- --json` despeja a
  árvore crua (útil para criar fixtures novas a partir de hardware real).

## Pontos para o líder decidir

1. **Akko S9 Ultra (36eb:1087) aparece como `Headset`.** No udev o dongle tem 3 interfaces de
   áudio (captura e reprodução) e só uma interface HID de Consumer Control; nenhuma de
   teclado. As fichas T07/T18 tratam-no como dongle de teclado. Se for mesmo teclado (talvez
   as interfaces de teclado só surjam com o teclado ligado), o `hid-perfis` vai corrigir
   o tipo na fusão, se a fusão der preferência ao tipo do provedor mais prioritário.
2. **Aparelho que muda** (ex.: o tipo só fica claro depois que o driver liga, ou um segundo
   aparelho igual sem serial renumera as instâncias) sai com `DeviceRemoved` e volta com
   `DeviceAdded`. Evitei `DeviceAdded` repetido para o mesmo id porque o contrato não diz
   como o daemon o trata. Se o contrato passar a definir "Added repetido = atualização",
   basta mudar `diff`.
3. `write` devolve `ReadOnly(Connection)` para qualquer valor, como pede a ficha (mesmo um
   `Dpi`, que pela lógica do core seria `Unsupported`).
4. `AsyncFd::new` está depreciado no tokio 1.54 em favor de `AsyncFd::register`, que é
   `unsafe`. Como a ficha não autoriza `unsafe`, usei `#[allow(deprecated)]` com comentário
   explicando por que a condição de segurança vale. Se preferir, troque por `register` com
   `// SAFETY:`.
5. O Magic Trackpad (05ac:0265) está numa porta marcada `fixed` direto no root hub, mas tem
   HID, então aparece. Webcam/leitor de digital internos sem HID somem.

## O que ficou de fora

- Bateria, DPI e qualquer outra capacidade (fora de escopo).
- Teste automatizado do monitor real (exige plugar hardware). A lógica de hotplug é testada
  com uma fonte falsa (`tests/hotplug.rs`); o caminho `SystemUdev::watch` só foi compilado e
  iniciado no `listar`, sem plug/desplug nesta sessão.
- Registro do provedor no `raizad` (cabe ao líder no merge): `raiza_provider_udev::UdevProvider::new()`.

## Como testar com hardware real

```sh
cargo run -p raiza-provider-udev --example listar
# com detalhes de por que cada aparelho foi ignorado e dos eventos udev:
RUST_LOG=raiza_provider_udev=debug cargo run -p raiza-provider-udev --example listar
```

Plugue e desplugue o mouse: deve sair uma linha `+ usb:24ae:1423:...` e uma `- usb:24ae:1423:...`
(~300 ms depois do evento). Para criar uma fixture a partir da máquina:
`cargo run -p raiza-provider-udev --example listar -- --json > arvore.json` (revise e troque
os seriais antes de commitar).
