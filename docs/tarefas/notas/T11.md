# T11: notas

## O que foi feito
Crate `crates/raiza-provider-evdev` (id `evdev`, `kind = Gamepad`).

- **Descoberta**: nós `eventN` com `ID_INPUT_JOYSTICK=1` via udev (`PadSource`/`SystemUdev`).
  Se o mesmo controle expõe mais de um nó, fica um por `DeviceId`, preferindo o que tem vibração.
- **Id**: USB → `DeviceId::usb_instance` a partir do dispositivo USB pai (serial, porta e
  portas do mesmo modelo sem serial lidas em `bus/usb/devices`); Bluetooth (`bustype 0005`)
  → `DeviceId::bluetooth(uniq)`; o resto → `DeviceId::Other`.
- **Bateria** (`Sysfs`): o `power_supply` cuja `device` aponta para um ancestral do input
  (até o dispositivo HID ou USB). `capacity` + `status`; sem `capacity`, `capacity_level`
  vira 5/20/50/80/100. Supply com `type` diferente de `Battery` é ignorado.
- **Rumble**: anunciado só se `capabilities/ff` do input tem o bit `FF_RUMBLE` (0x50).
  `max_duration_ms: 2000`, `writable: true`. `write` relê o estado, valida com
  `CapabilityValue::validate` e depois monta um `Pulse` (limites de novo); o backend só
  recebe `Pulse`, que não se constrói fora dos limites. Intensidade 0–100 → 0–0xFFFF.
  Intensidade ou duração 0 não toca no hardware. O backend real (`EvdevRumble`) sobe o
  efeito, toca, para e remove (drop do `FFEffect`).
- **Eventos**: monitor udev (`input` e `power_supply`) integrado ao tokio, sem polling,
  com debounce. Bateria mudou → `CapabilityChanged`; controle novo/removido ou mudança de
  forma → `DeviceAdded`/`DeviceRemoved`.
- **I/O injetável**: `PadSource`, `Sysfs::new(raiz)` e `RumbleBackend`.

## Testes
Sysfs falso em diretório temporário (`tests/common`), incluindo `capacity_level`,
limites do rumble (o `Gravador` nunca recebe valor fora do limite), hotplug e bateria.

## Fora do escopo / pendente
- Registrar o provedor no `raizad` (líder).
- Não há força de ganho (`set_ff_gain`) nem tipos de efeito além de `FF_RUMBLE`.

## Teste com hardware real
1. Conecte um controle (USB ou Bluetooth) com driver no kernel (`hid-playstation`, `xpadneo`...).
2. Confira `ls /sys/class/power_supply/` e `cat /sys/class/input/input*/capabilities/ff`.
3. Liste/leia via `raiza-ctl` e dispare um pulso de vibração (ex.: 50%, 500 ms).
4. Desconecte o controle e veja o `DeviceRemoved`.
Obs.: o `uaccess` do systemd precisa dar acesso ao `/dev/input/eventN` na sessão local.
