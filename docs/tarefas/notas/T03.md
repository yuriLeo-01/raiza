# Notas da tarefa T03: CI no GitHub Actions

## O que foi feito

- Criado `.github/workflows/ci.yml` com execução em todo `push` e `pull_request`:
  - Job `check` em `ubuntu-latest`: instala as dependências de sistema (`libudev-dev`, `libhidapi-dev`, `libdbus-1-dev`, `libgtk-4-dev`, `libadwaita-1-dev`, `pkg-config`), configura a toolchain `stable` via `dtolnay/rust-toolchain@stable` com `rustfmt` e `clippy`, configura cache via `Swatinem/rust-cache@v2` e executa `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` e `cargo test`.
  - Job `audit` separado em `ubuntu-latest` com `continue-on-error: true`: instala `cargo-audit` via `taiki-e/install-action@v2` e executa `cargo audit` sem bloquear PRs ou pushes em caso de falha.
- Criado `rust-toolchain.toml` com `channel = "stable"` e componentes `rustfmt` e `clippy`.
- Criado `rustfmt.toml` com opções estáveis alinhadas à edição 2024 (`edition = "2024"`, `max_width = 100`, `newline_style = "Unix"`).
- Criado `clippy.toml` com `msrv = "1.85"`, alinhado ao `workspace.package.rust-version` do `Cargo.toml` raiz.

## O que ficou de fora

- `actionlint` não estava instalado neste ambiente; a sintaxe YAML foi validada com `python3` (`yaml.safe_load`) e revisão manual da estrutura do workflow.
- `cargo-audit` e `cargo-deny` não estavam instalados neste ambiente; o comando `cargo audit` será validado na execução do workflow no GitHub Actions. Optou-se por `cargo audit` em vez de `cargo deny` porque `deny.toml` está fora do escopo da tarefa.
- A instalação de pacotes `apt-get` (`libudev-dev`, `libhidapi-dev`, etc.) não foi executada localmente por se tratar de ambiente Arch Linux.

## Como testar com hardware real

Não aplicável (tarefa de infraestrutura de CI, sem interação com dispositivos). Para validar o workflow remotamente, basta abrir um PR ou fazer push no GitHub após a integração na `main`.
